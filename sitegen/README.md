# Русская и английская версии

Редакция `product-20261109` охватывает 24 страницы: две главные, восемь прежних тематических страниц Таро и 14 новых страниц Астро. URL определены в `routes.json`; тексты — `content/ru.json` и `content/en.json`. Прежние HTML и стили остальных 18 языков защищены SHA-256 в `legacy-integrity.json`. `/en/` остаётся перенаправлением; `/en/<topic>/` — самостоятельными страницами.

Генерация и проверка из чистого checkout требуют только Python 3.10+:

```sh
python3 sitegen/generate.py
python3 sitegen/generate.py --check
python3 sitegen/validate.py
python3 -m http.server 8765 --bind 127.0.0.1
```

Браузерная проверка требует Playwright и Chromium. Она посещает только локальный HTTP сервер; отчёт и снимки сохраняются вне репозитория:

```sh
python3 sitegen/browser_check.py --base http://127.0.0.1:8765 --output /tmp/taro-site-qa
```

Генератор обновляет только указанные RU/EN HTML и соответствующие записи sitemap. Он не вводит сборщик или runtime-зависимость: GitHub Pages публикует готовые файлы. Не запускать старый игнорируемый `tools/generate_site.py` для новой редакции: он рассчитан на прежнюю схему контента.

Три входа в `generate.py` должны совпадать с действующим master и проверенным реестром URL. Браузерный `?ref=` требует Taro schema105 и backend r75 или совместимого преемника. Основной бот и Астро сохраняют `start=ref974025936`; Астро сначала открывает чат, затем приложение кнопкой. Клик не означает регистрацию или получение бонуса.

`images/en/app-*.webp` — снимки настоящего опубликованного интерфейса r74/r75 с полностью подменёнными демонстрационными API-данными, без реальных аккаунтов, вопросов или результатов. `product-images.json` фиксирует происхождение, размеры и хеши. Иллюстрация hero переиспользует существующий рисунок в WebP. Эти файлы не генерируются при сборке сайта.

Перед публикацией: проверка генерации, валидация, браузерная матрица, редакторская сверка и готовность трёх входов. Публикация — обычный fast-forward push собственного репозитория в `main`; CNAME сохраняется. При регрессии подготовить обратный коммит выпуска, проверить его локально и опубликовать тем же способом. Не применять force push. После Pages build проверить HTTPS, 24 страницы и точное совпадение изменённых файлов с опубликованными байтами.

Индексация, поисковые позиции, AI citations и полевые Core Web Vitals подтверждаются только внешними данными. После выпуска владелец может отправить sitemap в Search Console/Bing и проверить URL; доступ к этим сервисам не входит в сборку сайта.
