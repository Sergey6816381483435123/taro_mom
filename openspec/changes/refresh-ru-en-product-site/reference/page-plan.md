## Общая модель страницы

- Один предметный h1 и ответ в первом абзаце: что это, зачем пользоваться и как начать. Локализованные title/description/OG/Twitter, breadcrumbs на detail.
- Три видимых обычных ссылки в порядке Тарошенька → Астро Mini App → браузер. RU-подписи: «Открыть Тарошеньку», «Открыть Астро Mini App», «Открыть в браузере». EN: “Open Taroshenka”, “Open Astro Mini App”, “Open in browser”. При двухшаговом запуске Mini App рядом пояснить действие кнопкой в Telegram.
- В каждом видимом повторении полного entry block сохранять порядок. Одиночный compact CTA допустим только для первого входа и не заменяет полный блок в hero и конце main.
- Реальный пример интерфейса по теме с локализованным alt/подписью; без личных вопросов, реальных имён, email, остатков баланса и выдуманных элементов UI. На макетах с демонстрационным содержимым указывать, что это пример.
- Условия доступа, необходимые исходные данные, ограничения, FAQ с конкретными ответами, полный disclaimer, связанные полезные страницы и повтор входов.
- Переключатель языка ведёт на эквивалент той же темы. При отсутствии перевода — явно подписанная ссылка на языковую главную, без фиктивной эквивалентности и hreflang.

## Главная

1. Бренд и hero: персональные расклады Таро с AI, без обещаний будущего. Три входа сразу после основного объяснения, первый визуально основной.
2. Три шага: выбрать сценарий → ввести вопрос/контекст, когда он нужен → изучить карты и интерпретацию. Не требовать вопрос для каждого формата.
3. Каталог по задачам: короткий ориентир; отношения; разбор ситуации/следующий шаг; глубокие расклады. Отразить актуальный каталог, а не старую схему четырёх Premium.
4. Пример интерфейса расклада/карты; AI-интерпретация и справочное значение карты объясняются отдельно.
5. Продолжение расклада, история, профиль/колоды/язык; справка карт как опциональная настройка. Колесо — отдельная дополнительная функция, без гарантии выигрыша.
6. Астро: короткое объяснение и ссылки на overview и содержательные темы. Таро сохраняет приоритет в hero/навигации/основном объёме.
7. Бесплатное начало, кредиты и Premium; цена/доступ перед подтверждением. Общий аккаунт только при той же/связанной identity.
8. FAQ; существующие языковые версии; disclaimer; три входа.

## Изображения и композиция

Обе исходные reference-картинки осмотрены. Сохраняются тёмный сине-фиолетовый интерьер, бирюзовое/сиреневое свечение, тёплые свечи, карты/кристаллы и тонкая anime-иллюстрация. Существующие сжатые иллюстрации переиспользуются. Новое AI-искусство не обязательно: центральное дополнение — изображения настоящего интерфейса.

- Hero: существующая иллюстрация с безопасным crop; рядом самостоятельный HTML-текст и три входа, никогда текст внутри изображения.
- Главная: один curated product screenshot расклада/карты и один Астро-preview; desktop показывает их рядом с объяснением, mobile последовательно.
- Detail: один тематический UI-пример; reuse допустим при совпадении смысла. Отдельная иллюстрация для каждой страницы не требуется.
- Product assets: оптимизированные WebP/AVIF с fallback, реальные размеры, responsive variants при необходимости, английские имена под `/images/en/` с суффиксом `-ru`/`-en` для UI-текста. QA screenshots остаются локальными артефактами вне публикации.
- От 320 px: одна колонка, ссылки переносятся внутри контейнера. При 768+ допустимы две колонки; минимум 44 px высоты основных touch controls. Sticky UI только при доказанной пользе и с safe-area; базовый вариант — без него.
