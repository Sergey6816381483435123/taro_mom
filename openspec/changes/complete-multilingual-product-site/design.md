## Context

Существующие 20 языков имеют по пять страниц Таро. RU/EN дополнительно содержат семь страниц Астро и новый шаблон. Все версии должны описывать один продукт с одинаковыми фактами и тремя входами.

## Goals / Non-Goals

**Goals:** 240 полностью локализованных страниц, единый актуальный дизайн, нативные снимки интерфейса, полноценная навигация между языками, проверенный GitHub Pages release.

**Non-Goals:** новые языки/страны, pSEO, backend/БД, изменение тарифов, функций или crawl-policy.

## Decisions

- Сохранить все прежние URL и корневой английский `/`; новые Астро-страницы размещать под существующим locale prefix `/xx/astro/<english-slug>/`. RU/EN пути не меняются.
- Один статический шаблон, реестр locale dir/lang/ogLocale и одинаковые взаимные alternate-ссылки на 20 языков плюс x-default. Выбор языка ведёт на соответствующую тему и работает без JS.
- Переводы готовятся ограниченными независимыми партиями в staging, затем основной агент проверяет структуру и переносит в source. Бренд `Tarot` на всех языках кроме русского `Тарошенька`. Продуктовые условия и полный disclaimer сохраняются.
- Снимки снимаются с реального frontend r76 при полной подмене API. Локализованные подписи приложения и демонстрационные тексты, только локальные карты `decks/rider_waite_classic`. Фиксируются хеши frontend, колоды и 60 WebP (три вида × 20 языков).
- Legacy integrity мигрирует: изменяемые по запросу 90 страниц выводятся из защиты, общие прежние assets, CNAME и `/en/` redirect остаются защищены исходными хешами.

## Risks / Trade-offs

- Пропущенный перевод или устаревшая оговорка → структурные и языковые проверки всех словарей, выборочная содержательная редактура важных утверждений.
- RTL и длинные надписи → логические CSS properties и браузерная матрица всех языков/типов страниц.
- Отсутствующие шрифты QA → Noto fallback для арабского/персидского, деванагари и корейского; проверка glyph coverage до снимков.
- Смешивание колод/личных данных → fail-closed маршрутизация capture, фиксированные demonstration fixtures и provenance с хешами Rider–Waite.

## Migration Plan

Сохранить baseline → единый генератор/контракт → переводы и снимки → статическая/браузерная проверка → один scoped commit/push → Pages build и public byte/HTTP acceptance. При регрессии публикуется обратный коммит выпуска без force push. Прежние локальные правки документации сохраняются.
